# 小游戏容量与性能

当前使用 Eva.js / PixiJS 的 Canvas 渲染器。`game/` 是源目录，只有生成的 `minigame/` 参与微信上传；原型归档、动作源、文档、测试与构建依赖不会进入运行包。

## 预算

`npm run build` 打包框架与业务代码，复制本地图片和音效。当前生成 37 个文件，约 2.534 MiB。`node tools/package-budget.cjs` 按完整生成目录计算，采用 **4 MiB 工程预算**并保留 64 KiB；最终上传体积和平台限额以微信开发者工具、CI 与平台配置为准。这个预算不沿用小程序 2 MiB 主包检查。

本轮全部资源本地加载，未启用分包或远程下载。新增普通怪图集、CG 和配乐前，应先确认目标平台额度，再按章节组织小游戏分包及 `wx.loadSubpackage` 加载状态、失败重试和共享资源引用；不能直接复用小程序页面分包配置。

## 性能路径

战斗与动画由单一 Eva 帧循环推进，延迟帧步长上限 50ms。精灵帧预切纹理；固定 UI 节点复用，文本内容变化时才更新，过期实体节点销毁，画面裁切到安全区域。控制器的 `setData` 仅合并本地对象，不经过 Page 桥；原来的跨桥数据量指标已归档。

渲染分辨率最高为设备像素比 2。当前选择 Canvas 兼容路径，尚未在微信低端机上测得稳定帧率；仅凭浏览器流畅不能判定真机性能。

## 真机记录

在低端与常用机型各跑一局，检查高敌人数、朱雀持续火区、三元素叠加和升级恢复，记录帧率、长帧、内存、触摸响应、前后台恢复、音频及发热。若 Canvas 成为瓶颈，再据测量结果评估 WebGL 适配、纹理合批与特效数量。
