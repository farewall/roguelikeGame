# 微信试玩上传

工作流 `.github/workflows/wechat-playtest.yml` 在推送 `wechat-playtest/**` 分支时执行，也可在 GitHub 提供入口时手动执行。只上传开发版本并生成临时预览二维码，不提审、不发布正式版。

## 操作与升级修复

- 通过左下角半透明摇杆连续移动，松手或取消触摸后摇杆归中并停止；战斗区域其他位置不会控制移动。已移除遁光按钮与逻辑。
- 人物只攻击周围淡圈内的敌人，按实际屏幕距离选择最近目标；范围以屏幕短边为基准缩放，敌人未进入范围时不攻击，也不消耗攻击冷却。
- 升级三选一暂停战斗。选择弹窗独立于战斗区和摇杆触摸区域，选项按 ID 与弹窗批次识别；轻触结束即可应用效果并关闭，后续生成的 tap 不会重复升级。敌人死亡与经验在弹窗前结算，防止重复奖励。
- 多次升级的经验会依次保留，当前选择先关闭并显示觉醒，再显示下一次选择，避免看起来一直没有退出。
- 战斗区域显示当前伤害与攻击间隔，升级后显示生效提示；火持续灼烧、水暂时减速、水火叠加爆发、地震荡附近敌人。

本地运行 `node --test tools/game.test.cjs` 验证移动、升级和结算回归；上传工作流会先执行相同检查。触控手感与微信原生按钮仍需真机试玩确认。

本次新增范围内外/边界、矩形场地距离、摇杆归中、触摸选中、取消/拖动、重复点击与连续升级回归。另用浏览器映射当前 WXML 和事件绑定，检查了摇杆触摸、六项升级生效与弹窗关闭；该检查不等价于微信真机验证。

## 横屏与游戏设置

应用与页面均使用 `pageOrientation: landscape`。人物图集、攻击范围与摇杆使用屏幕短边统一缩放，避免横屏后控件随屏幕宽度放大；升级选项采用横排三卡布局。

战斗右上角设置按钮会暂停移动、刷怪、冷却推进及待执行的升级/结算计时；关闭继续。切入后台也暂停，返回前台时若设置仍打开则保持暂停。退出需在游戏内确认，随后停止所有计时与音效并返回主菜单；当前局进度会丢弃。

音效开关、音量、震动和操作提示保存在本机。`miniprogram/audio/` 包含攻击、受击、升级、胜利和消散的短 PCM WAV；由 `node tools/prepare-audio.cjs` 离线生成，不依赖网络音频。设置中的「试听」用于检查当前开关与音量。

横屏、暂停/恢复、后台切换、退出清理、偏好持久化及音效播放调用均有逻辑回归；浏览器另检查了 844×390 与 667×320 的横屏布局、触摸操作、设置、升级和退出流程。仍需微信真机确认系统横屏切换、原生开关/音量组件与扬声器播放。

## 四向人物动作

待机、移动、普攻、受击、升级觉醒、神念消散均为四向六帧，共 144 帧。移动跟随行进方向，攻击按敌人在实际屏幕上的位置转向，收招后恢复行进朝向。原始动作图与浏览器预览见 `art/pangu-actions/`；主包仅包含压缩后的六张透明 PNG。

人物死亡时先停止战斗、完整播放神念消散，再显示失败结算；胜利时播放觉醒再显示成功结算。此版本不增加元素施法动作或按钮。

仓库 Settings → Secrets and variables → Actions：

- Repository secret `WECHAT_PRIVATE_KEY`：代码上传私钥全文，保留 PEM 首尾和换行。
- Repository variable `WECHAT_APPID`：对应小程序真实 AppID。

执行过程使用官方 `miniprogram-ci` 2.1.31，安装依赖由锁文件固定。密钥仅通过上传步骤的进程环境读取，不写入仓库或二维码 artifact。上传项目在临时目录中组装；AppID 仅替换临时配置，不修改仓库中的占位配置。

## 试玩

1. 打开仓库 Actions → WeChat playtest，确认本次提交对应任务成功。
2. 下载该次任务的 `wechat-preview` artifact，解压并在微信扫描 `qrcode.png`。预览有效期与可访问账号受微信限制；二维码 artifact 保留一天。
3. 也可在微信公众平台「版本管理」找到 CI 机器人 1 上传的开发版本，设置为体验版，并在「成员管理」添加体验者，再扫描体验版二维码。体验版设置不等于正式发布。

上传步骤若已提示 Development version uploaded 而二维码步骤随后失败，开发版本可能已经在后台，请先核对版本再重试。

## 常见阻塞

- 缺少变量/密钥：确认名称与以上完全一致。GitHub Secrets 不会自动注入本地云开发环境。
- invalid ip / IP whitelist：根据本次错误报告的上传出口 IP 配置微信公众平台「开发管理 → 开发设置 → 小程序代码上传」白名单。GitHub 托管 Runner 出口会变化；长期稳定上传宜使用固定出口的自托管 Runner。
- 签名/AppID 错误：确认私钥来自同一个 AppID 的「小程序代码上传密钥」，不是 AppSecret。重新生成私钥后要更新 Secret。
- 无扫码权限：在微信公众平台添加对应微信号为开发者或体验者，并使用相应版本二维码。

私钥不要放进项目目录、Git 提交、截图、日志或聊天。本工作流不需要 AppSecret。
